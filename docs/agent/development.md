# Development Rules

このルールは、yakugaku-quiz プロジェクトにおいてAIエージェントが開発・修正を行う際の基本方針です。

## 1. 基本方針

* 既存のコード・設計・ディレクトリ構成を尊重して実装してください。
* 必要以上に大きな変更を行わず、依頼された範囲を中心に修正してください。
* 可能な限りシンプルで、読みやすく、保守しやすい実装を優先してください。
* 大きな変更は一度に行わず、小さな単位で実装してください。
* 不要なリファクタリングや、依頼と関係のないコード変更は行わないでください。

## 2. 重要な変更

以下のような影響範囲の大きい変更は、独断で実施せず事前に提案してください。

* DBスキーマの大きな変更
* アーキテクチャやディレクトリ構成の変更
* 新しいライブラリ・パッケージの導入
* 既存機能の削除
* 大規模なリファクタリング
* AWS構成やインフラ構成の変更

必要な場合は、変更理由と影響範囲を簡潔に説明してください。

## 3. Django / Python

* Djangoの標準機能・一般的なベストプラクティスを優先してください。
* Viewに処理を集中させず、必要に応じてModel・QuerySet・Service等へ処理を分離してください。
* N+1問題を避けるため、必要に応じて `select_related` / `prefetch_related` を使用してください。
* 関数やメソッドは役割を明確にし、必要以上に複雑にしないでください。
* 不要な `print`、デバッグコード、コメントアウトされたコードを残さないでください。

## 4. セキュリティ

* パスワード、APIキー、AWS認証情報、`SECRET_KEY` 等の機密情報をコードに直接記載しないでください。
* 機密情報は環境変数や `.env` 等を利用してください。
* Djangoが提供するORM、CSRF対策、テンプレートエスケープ等の標準的なセキュリティ機能を適切に利用してください。

## 5. 修正時の考え方

既存コードを修正する場合は、まず現在の実装を確認したうえで変更してください。
原則として、
**既存実装を理解する → 必要な箇所だけ変更する → 周辺への影響を確認する**

という流れで作業してください。
