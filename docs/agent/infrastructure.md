# インフラ変更ルール
AWS、ネットワーク、本番用Docker、デプロイ、Terraformに関する作業では、このファイルのルールに従ってください。

## 作業前に確認するファイル
- `AGENTS.md`
- `docs/project-spec.md` の「AWSインフラ構成」
- 変更対象となる既存のインフラコードと設定ファイル

## 基本方針
- AWS利用料は月額3,000円以内を目標とする。
- 開発・AWS学習用途を前提とする。
- 高可用性よりもコストを優先する。
- EC2とRDSは原則として平日10:00〜22:00（日本時間）のみ稼働する。
- 既存構成を確認せず、新しいAWSリソースを追加しない。

## 現在使用しない構成
以下はユーザーの明示的な承認なく作成・有効化しないでください。
- NAT Gateway
- Application Load Balancer
- 2台目以降のEC2
- Auto Scaling Group
- RDS Multi-AZ
- Elastic IP
- AWS WAF
- 有料のVPCエンドポイント
- EC2・RDSの24時間稼働

## 事前確認が必要な変更
以下に該当する場合は、実装前に変更内容、理由、想定料金、影響範囲をユーザーへ説明し、確認を取ってください。
- 月額料金が増加する可能性がある変更
- 新しいAWSサービスまたはリソースの追加
- EC2またはRDSのインスタンスタイプ変更
- EC2・RDSの稼働スケジュール変更
- VPC、サブネット、ルートテーブルの変更
- セキュリティグループの公開範囲拡大
- IAM権限の追加または拡大
- データベース、ストレージ、DNSリソースの削除・置換
- Route 53レコードまたはCloudFrontオリジンの変更
- バックアップ保持期間の短縮またはバックアップの削除

## セキュリティ
- AWSアクセスキーやシークレットをコードへ記載しない。
- `.env`、秘密鍵、認証情報をGitへコミットしない。
- EC2からAWSサービスへアクセスする場合はIAMロールを優先する。
- IAMポリシーは最小権限とする。
- RDSのPublic accessを有効にしない。
- PostgreSQLの5432番ポートをインターネットへ公開しない。
- SSHの22番ポートを`0.0.0.0/0`へ公開しない。
- Gunicornの待受ポートを外部公開しない。

## CloudFront
- `/static/*`と`/media/*`はS3へ転送する。
- Djangoの動的ページはEC2へ転送する。
- ログイン、セッション、CSRF、回答結果を含む動的ページをキャッシュしない。
- S3バケットを直接公開せず、CloudFront経由で配信する。
- キャッシュポリシー変更時は、Cookie、クエリ文字列、ヘッダーへの影響を確認する。

## EC2・RDSの起動停止
- 起動時はRDSを先に起動する。
- RDSが`available`になったことを確認してからEC2を起動する。
- 停止時はEC2を先に停止し、その後RDSを停止する。
- EC2起動後、必要に応じてRoute 53のオリジン用Aレコードを更新する。
- 自動化処理を変更する場合は、失敗時のログと再実行方法を用意する。

## バックアップ
- RDS自動バックアップを無効化しない。
- データを削除・置換する前に復旧可能なバックアップを確認する。
- スナップショットを作成する場合は、作成理由と削除予定を明確にする。
- バックアップ削除はユーザーの確認なしに実行しない。

## Terraform
Terraformを導入または変更する場合は、以下を守ってください。
- `terraform fmt`と`terraform validate`を実行する。
- `terraform plan`で変更内容を確認する。
- `terraform apply`はユーザーの承認なく実行しない。
- `terraform destroy`は実行しない。
- `terraform.tfstate`と秘密情報をGitへコミットしない。
- リソースの削除・再作成が含まれる場合は、実行前に対象と影響を報告する。

## ドキュメント更新
インフラの仕様、料金方針、稼働時間、使用サービスを変更した場合は、同じ作業内で`docs/project-spec.md`も更新してください。
